# Doc|Pipe

Doc|Pipe is a powerful CLI tool designed to automate the generation of documentation and technical content using Large Language Models (LLMs). It acts as a bridge between your source code and AI, allowing you to define "pipelines" that transform code structures and templates into high-quality documentation.

## How it Works

Doc|Pipe scans your project for a configuration directory named `.dp`. It identifies what needs to be documented, which LLM to use for specific tasks, and how to build the prompt.

### The Workflow

```text
[ Source Code ] ----+
                    |
[ Prompt Template ] +--> [ Doc|Pipe ] --> [ LLM (Ollama/Gemini/OpenAI) ]
                    |          |                   |
[ .dp Config ] -----+          +-------------------+
                               |
                        [ Generated Doc ]
```

## Getting Started

To use Doc|Pipe in your project, create a `.dp` folder in your project root. This folder will house your configuration and prompt templates.

### 1. Configure your Models (`models.json`)
Define which AI models are available. You can assign "stereotypes" to models to use different AIs for different tasks (e.g., a fast model for summaries, a smart model for architecture).

**Path:** `.dp/models.json`
```json
[
  {
    "stereotype": "architect",
    "serverType": "ollama",
    "modelName": "llama3",
    "modelProviderURL": "http://localhost:11434",
    "temperature": 0.2
  },
  {
    "stereotype": "writer",
    "serverType": "gemini",
    "modelName": "gemini-1.5-pro",
    "timeOutSeconds": 120
  }
]
```
*Supported Server Types: `ollama`, `gemini`, `openapi` (OpenAI), `lm.studio`.*

### 2. Define your Documents (`documents.json`)
List the files you want Doc|Pipe to generate.

**Path:** `.dp/documents.json`
```json
[
  {
    "outputFile": "docs/Architecture.md",
    "stereotype": "architect",
    "prompt": "prompts/arch-template.hbs",
    "ps": "\n\nGenerated by DocPipe AI."
  }
]
```

### 3. Create Prompt Templates
Doc|Pipe uses **Handlebars** for templating. You can use special helpers to inject your source code directly into the prompt.

**Example Template (`.dp/prompts/arch-template.hbs`):**
```handlebars
Analyze the following Java source code and create a technical architecture overview:

\{{java-src-dump "src/main/java/de/myapp/core"}}

Please focus on the design patterns used.
```

## Powerful Features

### Source Code Dumping
The `{{java-src-dump "path"}}` helper automatically crawls the specified directory, finds all `.java` files, and wraps them in Markdown code blocks within your prompt. This gives the LLM the full context it needs.

### Smart Updates (Caching)
Doc|Pipe is efficient. It calculates a SHA-256 hash of your resolved prompt.
* If the prompt and source code haven't changed, Doc|Pipe **skips** the LLM call.
* This saves API credits and time.
* Hashes are stored in `.dp/content-hashes.properties`.

### Environment Variables
For sensitive data like API keys, Doc|Pipe looks for a `.env` file in your root directory:
```env
CHAT_GEMINI_APIKEY=your_api_key_here
CHAT_OPENAPI_API_KEY=your_openai_key
```

## CLI Usage

Run Doc|Pipe from your terminal. By default, it looks at the current directory.

```bash
# Run in current directory
java -jar docpipe.jar

# Run on a specific project path
java -jar docpipe.jar -r /path/to/your/project
```

### Arguments
* `-r`, `--root`: Specify the root directory of the project to process.

## Project Structure Example

```text
my-project/
├── .env                # API Keys
├── .dp/                # Doc|Pipe Configuration
│   ├── models.json     # LLM definitions
│   ├── documents.json  # Generation tasks
│   └── prompts/        # Handlebars templates
├── src/                # Your source code
└── docs/               # Where the magic happens (Generated files)
```
