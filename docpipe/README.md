# Doc|Pipe

Doc|Pipe is a powerful CLI tool designed to automate the generation of documentation and project content using Large Language Models (LLMs). It works by scanning your project for configuration files, resolving templates, and piping the context into your favorite LLM to produce high-quality output files.

## How it Works

Doc|Pipe follows a simple "Configuration-over-Code" approach. It looks for a special directory named `.dp` within your project folders.

### The Workflow

```text
[ Your Project ]
      │
      ├── .dp/ ──────────────────┐
      │   ├── models.json        │ (1) Load LLM Configs
      │   ├── documents.json     │ (2) Identify Tasks
      │   └── my-prompt.hbs      │ (3) Resolve Templates
      │                          │
      ▼                          ▼
[ Doc|Pipe Engine ] ────▶ [ LLM Provider ] (Ollama, Gemini, etc.)
      │                          │
      └──────────────────────────┘
            │
            ▼
      [ Output File ] (e.g., README.md, API.docs)
```

## Getting Started

### 1. The `.dp` Directory
To make a directory "Doc|Pipe enabled," create a folder named `.dp` inside it. This folder will hold your configuration and prompt templates.

### 2. Configure your Models (`models.json`)
Define which LLMs you want to use. You can assign "stereotypes" (aliases) to different models.

```json
[
  {
    "stereotype": "documentation-expert",
    "serverType": "ollama",
    "modelName": "llama3",
    "modelProviderURL": "http://localhost:11434",
    "temperature": 0.7
  },
  {
    "stereotype": "code-analyst",
    "serverType": "gemini",
    "modelName": "gemini-pro"
  }
]
```

**Supported Providers:**
*   **Ollama:** Local LLMs.
*   **Gemini:** Google's AI (requires `GOOGLE_API_KEY`).
*   **OpenAPI / LM Studio:** Any OpenAI-compatible API.

### 3. Define your Documents (`documents.json`)
Tell Doc|Pipe what files to generate and which prompt to use.

```json
[
  {
    "outputFile": "README.md",
    "stereotype": "documentation-expert",
    "prompt": "readme-template.hbs",
    "ps": "\n\nGenerated by Doc|Pipe"
  }
]
```

### 4. Create a Prompt Template
Doc|Pipe uses **Handlebars** for templating. You can use special helpers to inject project context automatically.

**Example `readme-template.hbs`:**
```handlebars
# Project Documentation

This project contains the following Java source code:

{{java-src-dump "src/main/java"}}

Please summarize the logic above.
```

## Powerful Template Helpers

Doc|Pipe provides built-in helpers to gather context:

*   `{{java-src-dump "path"}}`: Recursively finds all `.java` files in the specified path and dumps their content into the prompt wrapped in markdown code blocks.
*   `{{URL "url"}}`: Fetches content from a local or remote URL to include in your prompt.

## Smart Updates (Caching)

Doc|Pipe is efficient. It calculates a SHA-256 hash of your resolved prompt. 
*   If the prompt hasn't changed, Doc|Pipe **skips** the LLM call.
*   If you change the template or the source code (if using `java-src-dump`), Doc|Pipe detects the change and regenerates the file.

The hashes are stored in `.dp/content-hashes.properties`.

## Usage

Run the application via CLI. By default, it looks in the current directory.

```bash
# Run in current directory
java -jar docpipe.jar

# Run on a specific project path
java -jar docpipe.jar -r /path/to/my-project
```

### Environment Variables
For cloud providers like Gemini or OpenAI, you can provide API keys via a `.env` file in the execution directory:

```env
CHAT_GEMINI_APIKEY=your_google_api_key
CHAT_OPENAPI_API_KEY=your_openai_key
```

## Summary of Configuration Files

| File | Purpose |
| :--- | :--- |
| `.dp/models.json` | Defines LLM connections and stereotypes. |
| `.dp/documents.json` | Lists the files to be generated and their templates. |
| `.dp/*.hbs` | Your prompt templates (Handlebars). |
| `.dp/content-hashes.properties` | (Auto-generated) Tracks changes to avoid redundant LLM calls. |
