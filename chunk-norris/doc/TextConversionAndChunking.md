# Document Conversion Mechanism in Chunk Norris

The `DocConversionRouter` is the central orchestrator for transforming documents from one format to another. It treats the conversion process as a graph problem, finding the most efficient path between a source format and a target format using a set of available conversion agents.

## Core Architecture

### 1. Graph-Based Routing
The system models document formats as **vertices** and `DocConversionAgent` implementations as **weighted edges** in a directed graph.

- **Nodes:** `DocArtifaktType` (e.g., PDF, HTML, Markdown).
- **Edges:** `DocConversionAgent` (the logic that converts Format A $\rightarrow$ Format B).
- **Weights:** Calculated based on estimated costs, quantity of artifacts, and accuracy requirements.

### 2. Pathfinding Logic
To determine the best conversion sequence, the router follows this priority:

1.  **Predefined Routes:** It first checks `ConversionRoutesConfig` for manually defined "golden paths" between specific formats.
2.  **Dynamic Pathfinding (Dijkstra):** If no predefined route exists, it builds a graph of all available agents and uses **Dijkstra's Shortest Path Algorithm** to find the "cheapest" route.

### 3. Cost Estimation & Accuracy
The "weight" of an edge is not static; it is calculated dynamically via `estimateConversionCosts`:

$$\text{Total Cost} = (\text{Estimated Cost} \times \text{Quantity}) + \text{Surcharge}$$

- **Accuracy Surcharge:** If an agent's accuracy rank is lower than the requested `ConversionAccuracy`, a significant penalty (`inaccurateSurcharge`) is added to the cost, steering the router toward more accurate (though potentially more expensive) agents.

## Conversion Workflow

The conversion process follows these steps:

1.  **Path Discovery:** `findBestPath()` identifies the sequence of agents needed to reach the target format.
2.  **Recursive Execution:** The `doConversion` method applies the agents sequentially.
3.  **Hierarchical Processing:** Because documents can be split into chunks, the router recursively applies the remaining agent chain to all child artifacts generated by a previous conversion step.
4.  **Collection:** Finally, the `DocContentCollector` aggregates the resulting content from the final format.

## Key Components

| Component | Responsibility |
| :--- | :--- |
| `DocConversionAgent` | Defines source/target formats and performs the actual transformation. |
| `DocArtifakt` | Represents the document/chunk being processed. |
| `ConversionRoutesConfig` | Provides hardcoded overrides for specific format pairs. |
| `DocContentCollector` | Extracts the final text or artifact data after the chain is complete. |
